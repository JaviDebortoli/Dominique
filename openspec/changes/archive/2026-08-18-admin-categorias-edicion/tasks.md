## Phase 1: Category Service — Rename + Delete

- [x] 1.1 RED: extend `src/modules/catalog/category.service.test.ts` (same real-Postgres, `randomUUID()`-suffix, `afterAll`-cleanup conventions as the existing `createCategory` suite) — `renameCategory`: persists the new `name` and leaves `slug` byte-identical; rejects a name colliding case-insensitively with another category (`"BIJOU"` vs existing `"bijou"`) via `DuplicateCategoryNameError`, writing nothing; **allows** a case-only self-rename (`"Bijou"` → `"bijou"` on the same row); a name containing `%` does not falsely collide with an unrelated existing name (documents the `ILIKE` wildcard risk from design.md's Open Questions — if it leaks, fall back to the `findMany` + `toLocaleLowerCase()` comparison documented there); unknown id → `CategoryNotFoundError`. `deleteCategory`: removes an empty category; throws `CategoryHasProductsError` with the exact `productCount` and deletes nothing when products reference it (seed a product against the category first); unknown id → `CategoryNotFoundError`.
- [x] 1.2 GREEN: add to `category.service.ts` — `DuplicateCategoryNameError` (`this.name = "DuplicateCategoryNameError"`, carries `name`), `CategoryNotFoundError` (carries `categoryId`), `CategoryHasProductsError` (carries `categoryId` + `productCount`, message `Category ${id} still has ${productCount} product(s) assigned.`), `RenameCategoryInput` (`{ name: string }`, no `slug` field — structurally unwritable per E1/E2/E4). `renameCategory(prisma, id, input)`: `findFirst({ where: { name: { equals: input.name, mode: "insensitive" }, NOT: { id } } })` → throw `DuplicateCategoryNameError` if found, else `prisma.category.update({ where: { id }, data: { name: input.name } })` catching `P2025` → `CategoryNotFoundError`. `deleteCategory(prisma, id)`: `prisma.category.delete({ where: { id } })`, catch `P2003` → `prisma.product.count({ where: { categoryId: id } })` → `CategoryHasProductsError`, catch `P2025` → `CategoryNotFoundError` (E3: DB constraint stays the single authority, count only runs on the already-failed path).

## Phase 2: `PATCH` + `DELETE /api/admin/categories/[id]` Route

- [x] 2.1 RED: create `src/app/api/admin/categories/[id]/route.test.ts` (mirrors `api/admin/orders/[orderId]/pickup/route.test.ts` and the existing `api/admin/categories/route.test.ts`: `vi.mock("@/lib/auth", () => makeAuthMockModule())`, real Postgres, seed a category row per test via `prisma.category.create` or the service) — `PATCH`: 200 with `{ id, name, slug }` and unchanged `slug`; 400 `invalid_request` for unparseable JSON and for missing/empty (post-trim) `name`; 400 `slug_immutable` when the body carries a `slug` key at all, even alongside a valid `name`, asserting the DB row is untouched; 401 with no session, mutates nothing; 404 `category_not_found` for an unknown id; 409 `duplicate_name` with a readable `message` on a case-insensitive collision, mutates nothing. `DELETE`: 200 `{ id }` on an empty category, row gone after; 401 with no session, deletes nothing; 404 `category_not_found` for an unknown id; 409 `category_has_products` with `productCount` in the body when products reference the category, and the category still exists after.
- [x] 2.2 GREEN: create `src/app/api/admin/categories/[id]/route.ts` — module doc referencing `src/proxy.ts` (not `middleware.ts`, D7/E-series), `interface RouteContext { params: Promise<{ id: string }> }` mirroring the pickup route. `PATCH`: `auth()` 401 gate first, parse JSON (catch → 400 `invalid_request`), reject if `"slug" in body` → 400 `slug_immutable`, trim `name`, reject empty → 400 `invalid_request`, `await context.params`, call `renameCategory`, catch `DuplicateCategoryNameError` → 409 `duplicate_name`, `CategoryNotFoundError` → 404 `category_not_found`, else rethrow (500). `DELETE`: `auth()` 401 gate, `await context.params`, call `deleteCategory`, return `{ id }` 200, catch `CategoryHasProductsError` → 409 `category_has_products` with `productCount`, `CategoryNotFoundError` → 404 `category_not_found`, else rethrow.

## Phase 3: Admin UI — Category Row (Edit + Delete)

- [x] 3.1 RED: create `src/app/admin/(console)/categorias/CategoryRow.test.tsx` (mirrors `NewCategoryForm.test.tsx`: `@testing-library/react` + `user-event`, stubbed `fetch`, stubbed `window.confirm`, mocked `next/navigation`'s `useRouter`) — clicking `Editar` swaps the name cell to a text input seeded with the current `name`; `Escape` and `Cancelar` restore the view without calling `fetch`; `Guardar` `PATCH`es `/api/admin/categories/{id}` with a body containing `name` and **never** a `slug` key, and calls `router.refresh()` on a 200; a stubbed non-2xx PATCH response renders its `message` in a `role="alert"` element within the row and does not call `router.refresh()`; clicking `Eliminar` when `window.confirm` returns `false` sends no `DELETE` request; when `confirm` returns `true` it sends `DELETE /api/admin/categories/{id}` and calls `router.refresh()` on 200; a stubbed non-2xx DELETE response renders its `message` in `role="alert"`.
- [x] 3.2 GREEN: create `src/app/admin/(console)/categorias/CategoryRow.tsx` (`"use client"`) — props `{ category: AdminCategoryRow }`, local `mode: "view" | "edit"`, `name` input state seeded from `category.name` on entering edit, `errorMessage` state. View mode: `<tr>` with name/slug/`productCount` text cells, `Editar`/`Eliminar` text-button actions (`font-sans text-label-caps uppercase tracking-widest`, `text-ink`/`text-red-700`). Edit mode: name cell becomes `<input className="border border-ink/20 px-3 py-2">`, slug cell renders `/categoria/{category.slug}` in `text-outline` (uneditable — the deliberate confusion-surfacing detail from design.md's UI Shape), actions become `Guardar`/`Cancelar`; `Escape` cancels, `Enter` submits (form `onSubmit`). `Guardar` → `fetch(PATCH, { body: JSON.stringify({ name }) })`; on error render `message` in `role="alert"`, on 200 call `router.refresh()` and return to view mode. `Eliminar` → `confirm(`¿Eliminar "${category.name}"?
