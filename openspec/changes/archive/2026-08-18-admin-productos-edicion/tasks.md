- [x] 1.3 RED: extend `product.service.test.ts` — testing-strategy item **(3)**: `deleteProduct` throws `ProductHasHistoryError` with exact `orderItemCount`/`stockMovementCount` and deletes nothing when a variant has an `OrderItem` row; succeeds on a clean product and cascades its variants + images away. Item **(4)**: throws `ProductHasStockError` naming the SKU for a variant with `onHand > 0` **and no `StockMovement` row** — the case `RESTRICT` cannot see (F2); unknown product id → `ProductNotFoundError`.
- [x] 1.4 GREEN: add to `product.service.ts` — `ProductHasStockError` (carries `productId`, `skus: string[]`), `ProductHasHistoryError` (carries `productId`, `orderItemCount`, `stockMovementCount`). `deleteProduct(prisma, id)`: `findUnique({ where: { id }, select: { variants: { select: { id, sku, onHand } } } })`, null → `ProductNotFoundError`; any `onHand > 0` → `ProductHasStockError` with the offending SKUs (F2/F3, pre-check — DB cannot express this constraint); `prisma.product.delete({ where: { id } })` (cascades Variants+Images per schema), catch `P2003` → `count(OrderItem)` + `count(StockMovement)` across the product's variants → `ProductHasHistoryError` (E3 pattern: DB is the authority for history, the catch only explains).
- [x] 1.5 RED: extend `product.service.test.ts` — testing-strategy item **(5)**: `deleteVariant` throws `LastVariantError` when one variant remains, even if that variant is clean; throws `VariantHasStockError` for `onHand > 0`; throws `VariantHasHistoryError` for an `OrderItem`/`StockMovement` row; succeeds on a clean non-last variant; unknown variant id → `VariantNotFoundError`.
- [x] 1.6 GREEN: add to `product.service.ts` — `VariantNotFoundError` (carries `variantId`), `LastVariantError` (carries `productId`, `variantId`), `VariantHasStockError` (carries `variantId`, `sku`, `onHand`), `VariantHasHistoryError` (carries `variantId`, `orderItemCount`, `stockMovementCount`). `deleteVariant(prisma, variantId)`: `findUnique` the variant (null → `VariantNotFoundError`), `variant.count({ where: { productId } }) === 1` → `LastVariantError` (F4, checked first — unconditional, different remedy in kind), `onHand > 0` → `VariantHasStockError`, `prisma.variant.delete`, catch `P2003` → counts → `VariantHasHistoryError`. **No** interactive `$transaction` (F4 — every writer that raises `onHand` also writes a `StockMovement`, so no live TOCTOU window exists).
- [x] 1.7 RED: extend `product.service.test.ts` — testing-strategy item **(6)**: `updateVariant` changes `sku`; rejects a duplicate `sku` with `DuplicateSkuError`; rejects a `size`/`color` change that collides with a sibling's *resolved* pair (patch merged over current values) via `DuplicateVariantError` (F5). Item **(7)**: rejects `size`/`color` with `VariantAttributesImmutableError` once an `OrderItem` exists on that variant, while an `sku`-only change on the same variant still succeeds.
- [x] 1.8 GREEN: add to `product.service.ts` — `DuplicateSkuError` (carries `sku`), `VariantAttributesImmutableError` (carries `variantId`, `orderItemCount`), `UpdateVariantInput` (`{ sku?, size?, color? }`, no `onHand`/`held` field — F7). `updateVariant(prisma, variantId, input)`: `findUnique` the variant (null → `VariantNotFoundError`); if `input.size` or `input.color` present, `count(OrderItem)` for the variant > 0 → `VariantAttributesImmutableError` (F6); resolve the pair (patch merged over current `size`/`color`) and `findFirst({ productId, size, color, NOT: { id: variantId } })` → `DuplicateVariantError` if found (F5, reuses the shipped error, checked before the `sku` write so a surviving `P2002` is unambiguously `sku`); `prisma.variant.update`, catch `P2002` → `DuplicateSkuError`.
